# 从本地代码到微信真机

## 现在的状态

当前工程已配置 AppID `wxd66f4d28e0aa952e` 和开发环境 `cloud1-d2g1nqof255e7c8b3`；本机开发者工具已登录，2026-10-04 已升级排课相关的三个云函数。原生联调进展与未验证项以 [验收记录](ACCEPTANCE.md) 为准，不要用历史 HTML 预览判断新版已经上线。

下面保留从零接入的步骤，供换电脑或接入自己的小程序时使用；已经完成的配置不必重复创建。顺序是：**装工具 → 确认小程序主体 → 取得 AppID → 创建测试云环境 → 配置并部署 → 真机验收 → 再考虑发布**。

## 1. 安装微信开发者工具（你手动完成）

从 [微信官方开发者工具下载页](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html) 下载稳定版，选与你的 Mac 芯片匹配的版本。安装后用有开发权限的微信扫码登录。此官方页面在本轮自动读取受限，下载按钮名称和最新版本号以官网为准，不使用第三方安装包。

这里需要的是“微信开发者工具”，不是另一个 AI 开发助手。网页只能演示设计，真正的小程序编译、微信接口、二维码预览和真机测试需要该工具。

## 2. 注册/确认小程序与 AppID（你手动完成）

1. 打开 [微信公众平台](https://mp.weixin.qq.com/)，确认已有小程序；没有则按平台流程注册小程序主体。
2. 完成平台当前要求的主体、管理员和类目资料。主体资格、认证、备案与发布要求以平台当前提示为准；不要为了测试随意填写不真实信息。
3. 在小程序的开发设置/开发管理中找到 AppID。它通常以 `wx` 开头，**不是 AppSecret**。
4. 将你的扫码微信加入该小程序的开发者或管理员名单。

可以给助手 AppID 和云环境 ID 以协助填写配置。不要发送微信登录二维码、验证码、密码、AppSecret 或支付信息。

## 3. 导入工程

开发者工具选择“导入项目”，目录选整个 `course-check` 仓库，而不是只选 `miniprogram` 子目录。

- 根配置已经指定 `miniprogramRoot: miniprogram/`、`cloudfunctionRoot: cloudfunctions/`。
- 换用另一个小程序时，修改根 `project.config.json` 的 `appid`；当前仓库已有真实 AppID，不需要再次替换。
- `touristappid` 只是公开模板占位，不代表已经具备云开发权限。
- 建议使用工具提供的当前稳定基础库；文件导出使用的 `wx.shareFileMessage` 至少需要基础库 2.16.1。[微信官方接口类型说明](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)

## 4. 创建测试云环境

在开发者工具的“云开发”或与你的小程序关联的 CloudBase 控制台中创建/选择环境。先用测试环境，检查套餐、到期时间、费用和额度；**本轮没有开通付费资源**。不要把测试直接连到已有生产数据。

把环境 **ID** 填入 `miniprogram/config.js` 的 `env`。不是显示名称，也不是 AppID。云函数使用“当前所在环境”，所以四个函数必须部署到同一个选定环境。小程序关联 AppID、函数调用方式参见 [CloudBase 微信云函数接入说明](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)。

本工程走微信原生 `wx.cloud` 登录/调用链路，不另外混入 Web 端匿名登录。

## 5. 建立数据库与权限

创建三个集合：`users`（账户资料）、`courses`（课程）、`checkins`（上课记录）。空集合即可，不要手工插入假用户或填写别人的 `_openid`。

本工程所有读写都经云函数，前端不直接操作数据库。将每个集合设置为“仅管理端可读写”，或对应的自定义规则：

```json
{ "read": false, "write": false }
```

这会拒绝客户端直连，管理员云函数/控制台仍能读写。云函数另外从微信可信上下文取当前用户身份并检查归属。[CloudBase 官方权限示例](https://docs.cloudbase.net/rule/rule-example)

索引要在真实环境验证。如果控制台/函数日志提示缺少索引，按报错给出的查询建立复合索引，重点核对这些组合（不要把它们当作已经创建）：

| 集合 | 查询/排序用途 |
| --- | --- |
| courses | 当前用户、归档状态；创建时间倒序、ID 升序分页 |
| checkins | 当前用户、课程 ID、日期；日期倒序、ID 升序分页 |
| checkins | 当前用户按 ID 升序读取全部记录用于聚合 |
| users | 当前用户身份查询兼容旧资料 |

新记课使用由“用户＋课程＋日期”生成的固定记录 ID，加数据库事务保证重复提交不增加课时，不依赖你手动为含旧重复数据的集合贸然创建唯一索引。事务只在服务端运行，且有操作数限制。[CloudBase 事务说明](https://docs.cloudbase.net/database/transaction)

## 6. 部署四个云函数

如果改过排课规则，先在仓库根目录运行 `npm run sync:attendance`，再运行 `npm run verify`；`attendance.js` 必须随 `course`、`checkin`、`stats` 各自完整上传。旧手写排课数据无须批量迁移，用户在编辑课程中明确设置后才启用计划条目。

1. 在每个函数目录根据锁文件安装依赖，例如 `cd cloudfunctions/login` 后执行 `npm ci --ignore-scripts`，其余三个同样处理。
2. 在开发者工具选定测试云环境，将 `login`、`course`、`checkin`、`stats` 四个函数都上传/部署。部署选项以当前工具为准；要保证部署产物含锁定依赖，而非重新使用 `latest`。
3. 核对函数运行时支持该 SDK，查看构建/运行日志，不把“上传结束”当成业务验收。
4. 重新编译小程序。若出现缺少函数、无环境权限、缺少集合或索引错误，先处理配置，不要清空本地数据。

**升级要求：**先更新全部云函数，再发布新版客户端。旧扁平请求仍兼容，但旧客户端没有创建操作编号，不能承诺旧版本丢失回执后的新增去重。新版本会给每次创建一个固定编号，刷新和重试不会重复创建。

本轮复审还为课程、记录和统计请求增加了预期身份核对，防止账号变化后读写落入另一账号。此保护依赖新版云函数在读写前核对身份，不能只更新客户端；旧云函数会忽略新字段。接入后按验收清单测试身份不符时确实拒绝请求。

旧云端数据无需批量改 ID、无需重建集合。旧版无身份本地缓存不会自动上传新账号；“我的 → 导出旧版缓存备份”保留原内容，需要人工核对归属和日期后再处理。

## 7. 真机验收与发布

先按 `docs/ACCEPTANCE.md` 测试。文件分享、意见反馈、原生底栏、安全区、断网恢复必须在真实微信中确认。开发工具里点击成功不代表手机也成功。

验收后，再由管理员在微信平台完成当前要求的资料、隐私说明、类目、备案/审核及发布步骤。平台规则可能变化，按你账号当前后台提示核对。本轮没有代替你提交审核或发布。

## 管理后台到底有没有？

有两类现成入口，不需要一期另开发管理网站：

- **微信公众平台：**管理小程序身份、成员权限、版本、审核与发布。
- **云开发控制台：**查看数据库课程/记录、函数日志、存储、用量和费用，进行备份或人工排错。

小程序里的“我的”则供家长重试同步、恢复归档课程和导出数据。控制台不是给家长日常用的业务后台，不要向普通用户开放管理员权限。

修数据前先导出备份；不要直接改用户表的累计或连续天数字段，它们是旧派生值，新版从课程与记录重新计算。只有日后真的需要客服批量处理、多人审核、操作审计时，再设计独立管理台。
