## 2. 产品定义

### 2.1 一句话定义

这是一个面向家长或监护人的微信小程序，用来记录孩子的课外课程、每日上课打卡和完成进度，并在弱网或离线时保留操作，网络恢复后再同步到云端。

“面向家长或监护人”属于高置信推断。首页写有“记录宝贝的每一次进步”，空状态写有“记录孩子的每一次成长”，但数据模型中没有独立的孩子、家长或家庭实体。证据：`miniprogram/pages/index/index.wxml:9-14`、`miniprogram/components/empty-state/empty-state.js:17-25`。

### 2.2 核心价值

- 用最少步骤完成“添加课程 → 每日打卡 → 查看进度”的主流程。
- 把课程总课时、累计打卡、连续天数、近期趋势和月度表现集中展示。
- 在网络不稳定时先保存本地操作，减少因断网造成的记录丢失。
- 使用微信身份隔离不同用户的数据，不要求用户创建独立账号密码。

### 2.3 当前范围

当前端到端范围包括：

- 微信身份登录及用户记录初始化。
- 课程新增、查看、编辑、删除和分享入口。
- 每门课程每日一次的一键打卡。
- 课程历史记录与学习统计。
- 本地缓存、离线操作队列、自动同步和手动重试。
- 本地高级模式开关和版本信息。

以下内容不属于当前已交付范围：

- 家庭成员协作。
- 真正发送的上课提醒。
- 数据导出与邮件发送。
- 意见反馈提交。
- 成就系统。初始代码曾包含“成就”标签，当前代码已删除。
- 教师端、管理员端、付费、排课交易或教学内容管理。

## 3. 用户、身份与权限

### 3.1 用户角色

代码只定义了一类用户：当前微信用户。

- 小程序启动时调用 `login` 云函数取得 `OPENID`。
- 新用户会创建 `users` 记录；老用户会更新最后登录时间和登录次数。
- 当前用户只能查询或修改 `_openid` 与自己一致的课程、打卡和统计数据。
- 没有管理员、教师、孩子或家庭成员的权限模型。

证据：`cloudfunctions/login/index.js:12-100`、`cloudfunctions/course/index.js:46-56`、`cloudfunctions/checkin/index.js:38-48`、`cloudfunctions/stats/index.js:20-30`。

| AUTH-02 | 首次登录应创建用户记录 | 新记录包含身份、昵称、头像、连续天数、累计打卡、默认设置和时间戳 | 已证实 |

### 4.2 核心业务对象

1. 用户：由微信 `OPENID` 唯一标识。
2. 课程：用户要持续记录的学习项目。
3. 打卡：某门课程在某个自然日的一次完成记录。
4. 统计：由课程和打卡聚合得到的进度、频次和连续性指标。
5. 同步任务：离线时保存的新增、修改、删除或打卡操作。

## 5. 核心用户流程

### 5.1 首次使用

1. 用户打开小程序。
2. 应用初始化固定云环境 `course-check-env`。
3. 应用调用登录云函数；云端创建或更新用户记录。
4. 首页并行读取课程列表和统计总览。
5. 如果本地已有课程缓存，先显示缓存，再在后台刷新云端数据。
6. 如果没有课程，用户仍可通过“添加新课程”进入创建流程。

代码未在首页实际渲染已声明的空状态组件，因此“无课程时显示专门的新手引导”不能算当前能力。

### 5.2 添加课程

1. 用户从首页点击“添加新课程”。
2. 用户选择课程类型和图标，输入课程名称。
3. 用户可填写总课时、上课时间、备注和提醒设置。
4. 保存时，客户端先把课程写入本地缓存，并生成本地临时 ID。
5. 客户端把 `add_course` 操作加入同步队列，页面无需等待云端创建完成。
6. 云端创建成功后，客户端用云端 ID 替换本地临时 ID，并改写相关打卡缓存和后续队列项。

证据：`miniprogram/pages/course-edit/course-edit.js:88-201`、`miniprogram/utils/db.js:117-138`、`miniprogram/utils/sync-queue.js:212-234`、`miniprogram/utils/sync-queue.js:292-355`。

### 5.3 每日打卡

1. 用户在首页课程卡片或课程详情页点击“一键打卡”。
2. 客户端使用设备本地自然日生成 `YYYY-MM-DD` 日期。
3. 客户端先检查同一课程、同一日期是否已有记录。
4. 未重复时，客户端立即更新本地记录和课程计数，并加入同步队列。
5. 云端再次检查重复记录；重复请求返回 409。
6. 同步队列把 409 视为幂等成功，即重复重试不会再次增加记录。
7. 当天已经打卡后，首页按钮显示“今日已打卡”，详情页隐藏浮动打卡按钮。

证据：`miniprogram/utils/db.js:216-285`、`cloudfunctions/checkin/index.js:110-209`、`miniprogram/utils/sync-queue.js:173-194`。

### 5.4 查看课程进度

1. 用户点击课程卡片进入详情页。
2. 页面读取课程信息和最近 50 条打卡记录。
3. 页面显示累计课时、本月课时、总课时目标和完成百分比。
4. 历史记录按日期倒序显示，并以记录总数反向编号为“第 N 节课”。
5. 用户可下拉刷新。

当前详情页和课程卡片的进度百分比没有限制为 100%，超额打卡时可能显示大于 100%；云端课程排行则把进度限制为 100%。这是冲突，不应默认为产品规则。

### 5.5 查看学习统计

统计页当前从课程及其打卡记录在客户端计算以下内容：

- 课程总数。
- 累计打卡数。
- 当前连续打卡天数。
- 本月课时。
- 最近 7 个自然日的每日打卡数。
- 按打卡次数降序排列的课程排行。
- 最近 12 个月中所选月份的总课时、活跃天数和周均课时。

云端另有自然周统计、月历、热力图和多周趋势接口，但当前统计页没有调用这些接口。

### 5.6 离线与同步

1. 新增、编辑、删除课程，以及打卡、取消打卡，均先修改本地缓存。
2. 每个操作进入本地同步队列，初始状态为 `pending`。
3. 有网络时立即尝试同步；无网络时保留队列。
4. 应用启动约 2 秒后、回到前台、网络从离线恢复、用户手动点击同步状态时，均会触发同步。
5. 同一时刻只运行一个同步循环；同步期间加入的新任务会在当前循环结束后继续处理。
6. 队列向用户展示待同步、同步中和失败状态。
7. 已同步任务默认保留 7 天，失败任务继续保留。

证据：`miniprogram/app.js:12-54`、`miniprogram/utils/network-monitor.js:16-52`、`miniprogram/utils/sync-queue.js:16-165`、`miniprogram/components/sync-status/sync-status.js:45-90`。

## 7. 业务规则

| 编号 | 规则 | 当前代码定义 |
|---|---|---|
| BR-01 | 课程归属 | 每门课程只属于创建它的微信用户 |
| BR-02 | 课程名称 | 页面最多输入 20 个字符；云端允许最多 50 个字符；去除首尾空格后不能为空 |
| BR-03 | 课程类型 | 只接受 `swim`、`piano`、`english`、`art`、`dance`、`sports`、`music`、`other` |
| BR-04 | 总课时 | 可不填；默认 0；填写时必须为非负整数 |
| BR-05 | 上课时间 | 页面最多输入 50 个字符；云端未设置长度限制 |
| BR-06 | 备注 | 页面最多输入 200 个字符；云端未设置长度限制 |
| BR-07 | 提醒参数 | 默认关闭、提前 60 分钟；只接受 15、30、60、120 分钟 |
| BR-08 | 打卡唯一性 | 同一用户、课程和自然日只能有一条记录 |
| BR-09 | 日期 | 采用设备或云函数运行环境的本地日期，格式为 `YYYY-MM-DD` |
| BR-10 | 连续天数 | 允许连续序列结束于今天或昨天；更早则当前连续值为 0 |
| BR-11 | 进度 | 基础公式为 `打卡数 / 总课时 × 100%`；总课时为 0 时进度为 0 |
| BR-12 | 课程删除 | 默认调用软删除；硬删除参数为 `true` 时才删除课程及关联打卡 |
| BR-13 | 列表分页 | 课程和打卡默认第 1 页、每页 50 条 |
| BR-14 | 排序 | 课程按创建时间倒序；打卡按日期倒序；排行按打卡数倒序 |
| BR-15 | 热力图范围 | 查询天数被限制在 1 至 366 天 |
| BR-16 | 队列保留 | 已同步任务默认保留 7 天；待处理、同步中和失败任务保留 |

## 10. 非功能需求

### 10.1 平台与兼容性

- 运行平台为微信小程序并使用微信云开发。
- 云能力要求微信基础库 2.2.3 或以上。
- 页面和底部导航应适配设备安全区域。
- 组件按需懒加载。

### 10.2 可用性与离线能力

- 用户写操作应先在本地可见，再异步同步云端。
- 网络恢复和应用回到前台时应自动尝试同步。
- 同步失败不应丢弃本地任务。
- 用户应看到待同步和失败数量，并能手动重试。
- 云端读取失败时，课程和打卡应回退到本地缓存；统计应提供空数据或本地计算结果。

### 10.3 一致性

- 所有“今天”“本月”和连续天数计算应使用同一自然日口径，避免 UTC 日期导致跨时区偏移。
- 离线新建课程同步成功后，所有引用必须从本地 ID 迁移到云端 ID。
- 重复同步打卡不得增加第二条记录。
- 课程计数不得小于 0。

### 10.4 安全与隐私

- 所有业务云函数必须验证微信身份。
- 所有课程、打卡和统计查询必须按 `_openid` 限定。
- 更新接口只能接受白名单字段，不能修改归属、创建时间或删除状态。
- 硬删除必须由显式参数触发。
- 当前代码声明了位置权限，但没有使用位置功能。发布前应删除无用权限或补充明确用途。

### 10.5 性能

- 有缓存时，首页课程列表应优先返回缓存，避免等待云端。
- 课程和打卡列表默认每页最多 50 条。
- 同步队列串行处理任务，避免同一任务被并发重复执行。
- 当前没有响应时间、首屏时间或数据规模指标。
- 统计页会逐门课程串行读取打卡，课程数量增加后可能明显变慢，需要性能基线后才能定义容量要求。

### 10.6 错误处理与可观测性

- 网络、权限、业务、校验、服务端和未知错误应转为用户可理解的提示。
- 可重试错误允许立即重试或延迟重试。
- 未捕获异常和 Promise 拒绝应进入全局错误处理。
- 服务端和未知错误计划上报到 `logError` 云函数，但该云函数当前不存在。

### 10.7 交互与可访问性

- 主要操作应有加载、成功、失败和禁用状态。
- 动画应响应系统“减少动态效果”偏好。
- 页面使用自定义导航时应保留返回入口和底部安全区。
- 当前代码没有无障碍标签、键盘导航或颜色对比度的明确验收标准。

### 11.2 已发现的冲突和缺口

以下是代码事实，不是新增需求：

1. **课程详情模板存在明显语法残留。** `miniprogram/pages/course-detail/course-detail.wxml:116-117` 的开始标签后出现 `003e`，可能导致模板编译失败。
2. **“我的”页面引用了不存在的提示函数。** `profile.js` 导入并调用 `showToast`，但 `utils/util.js` 没有定义或导出它。手动同步、开发中提示和高级模式反馈可能直接报错。
3. **错误上报目标缺失。** `ErrorHandler` 调用 `logError` 云函数，但工程中没有该云函数；关键错误只能留在控制台。
4. **删除文案和真实行为冲突。** 确认框承诺“相关的所有打卡记录也会被删除”，但页面调用默认软删除。云端打卡仍保留，只有本地打卡缓存被清除。需要明确选择“隐藏课程并保留历史”或“彻底删除全部数据”。
5. **重试上限没有真正封顶。** 单次失败三次后任务标记为 `failed`，但后续每次同步仍会重新处理所有 `failed` 任务，重试次数会继续增加。
6. **课程类型视觉覆盖不完整。** 课程详情支持 8 种背景，但首页课程卡片样式只定义游泳、钢琴、英语。其余 5 类可能显示白色文字却没有课程背景。
7. **进度上限不一致。** 云端排行把进度限制为 100%，首页卡片和详情页不限制，超额打卡可能显示大于 100%。
8. **提醒只有数据，没有执行器。** 用户可以保存提醒开关和提前分钟数，但没有定时任务、订阅消息授权或消息发送代码。
9. **重复打卡缺少数据库级唯一约束。** 当前采用“先查再写”，并发请求存在同时通过检查的窗口。
10. **分页没有用户入口。** 详情页默认只取前 50 条记录，没有继续加载或翻页逻辑。
11. **缓存刷新可能覆盖未同步的乐观数据。** 后台云端刷新会直接替换课程缓存，未完成同步的本地变更缺少合并规则。
12. **权限声明与功能不匹配。** 位置权限和 `wxacode.get` 开放接口权限已声明，但当前代码没有对应功能。
13. **配置项未执行。** 同步超时 5000 毫秒已配置但未应用；`AUTH_TOKEN`、`LAST_SYNC` 等存储键也没有形成闭环。
14. **没有自动化测试。** 日期边界、连续天数、离线 ID 迁移、同步重试、用户隔离和删除语义都缺少回归保护。

## 12. 关键验收场景

以下场景适合作为后续验收测试基线：

### AC-01 首次登录

- 给定一个从未使用过小程序的微信用户。
- 当用户首次打开小程序。
- 则云端创建一条 `users` 记录，并返回 `isNewUser=true`。
- 且首页可以继续加载，不要求用户输入账号密码。

### AC-02 在线添加课程

- 给定网络可用且用户已登录。
- 当用户输入有效名称、选择课程类型并保存。
- 则课程立即出现在首页。
- 且云端创建记录后，本地临时 ID 被替换为云端 ID。

### AC-03 离线添加并打卡

- 给定设备断网。
- 当用户添加课程并对该课程打卡。
- 则课程和打卡立即在本地可见，两项操作进入待同步队列。
- 当网络恢复后，先创建云端课程，再用云端课程 ID 同步打卡。
- 且刷新页面后课程和打卡仍存在且不重复。

### AC-04 重复打卡

- 给定某课程今天已经有一条打卡。
- 当用户再次打卡，或同步队列重放同一打卡。
- 则用户收到“今天已经打卡”提示，云端记录总数不增加。

### AC-05 连续天数

- 给定用户连续三天有打卡，今天有打卡。
- 则连续天数为 3。
- 给定今天没有、昨天及前两天有打卡。
- 则连续天数仍为 3。
- 给定今天和昨天都没有打卡。
- 则当前连续天数为 0。

### AC-06 月份切换

- 给定最近 12 个月存在多个月份的打卡数据。
- 当用户选择任一月份。
- 则总课时、活跃天数和周均课时只使用该月份数据。
- 且切换回当前月份后恢复当前月统计。

### AC-07 用户隔离

- 给定两个不同 `OPENID` 的用户。
- 当两人分别查询课程、打卡和统计。
- 则任何返回结果都不包含另一用户的数据。

### AC-08 删除课程

该场景在产品决策前不能定稿：

- 方案 A：软删除后课程不显示，但云端打卡保留，可用于恢复或统计审计。
- 方案 B：删除课程时永久删除课程和全部关联打卡，且必须明确不可恢复。

当前页面文案指向方案 B，实际调用指向方案 A。

## 13. 待确认的产品决策

1. **删除语义：** 默认软删除还是永久删除课程及打卡？是否需要回收站和恢复入口？
2. **数据主体：** 一位微信用户是否只记录一个孩子？如果记录多个孩子，课程需要增加 `childId`，家庭成员也需要权限模型。
3. **提醒范围：** 提醒参数只是预留字段，还是必须通过微信订阅消息真正送达？
4. **进度含义：** 超过总课时后显示 100%、显示超额百分比，还是把课程标为已结课？
5. **后端能力是否面向用户：** 取消打卡、批量打卡、打卡详情、照片、热力图和趋势图是否属于近期范围？
6. **占位入口是否保留：** 家庭成员、导出和反馈在未实现时继续展示，还是在可用前隐藏？
7. **日期口径：** 使用设备时区、固定中国时区，还是使用用户配置时区？当前客户端和云函数都使用各自运行环境的本地日期。
8. **历史数据容量：** 单课超过 50 条、课程数量较多时，是否需要分页、增量加载和统计聚合缓存？

## 14. 从代码演变推断的产品方向

仓库只有一个初始提交，以下判断来自该提交与当前未提交代码的差异：

- 首页从两条写死的示例课程改为真实云端和缓存数据，说明主流程正在从视觉演示转为可用产品。
- “成就”标签已被移除，提醒、反馈等缺失页面被改为“开发中”，说明当前优先级集中在课程、打卡、统计三条主线。
- 日期处理从 UTC 字符串改为本地自然日并增加日期合法性校验，说明跨时区错日被视为真实风险。
- 课程字段增加类型、总课时和提醒校验，说明数据质量正在收紧。

## 16. 文档可信度结论

- 产品定位：高置信推断。
- 页面范围和核心流程：高可信，前端与云端代码可互相印证。
- 字段、默认值和接口：高可信，直接来自实现。
- 异常边界：中高可信，来自分支和错误码，但没有自动化测试证明。
- 离线一致性：中等可信，队列结构完整，但存在未同步数据合并和重试上限缺口。
- 家庭、提醒、导出、反馈等未来范围：低可信，只能确认存在占位入口。
- 生产可运行性：不能仅凭静态代码确认；至少需先解决 11.2 中的模板、提示函数和缺失云函数问题，并在微信开发者工具中完成端到端验证。
