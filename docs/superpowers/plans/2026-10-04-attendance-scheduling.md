# 排课与出缺席闭环实施计划

> **For agentic workers:** use `superpowers:subagent-driven-development` to implement this plan, with specification and quality reviews at each checkpoint.

**Goal:** 在现有单人记课小程序中接入已确认的排课、待确认、出缺席与扣课时设计，保留已有数据与 B 版页面。

**Architecture:** 复用 courses / checkins 与按账户隔离的离线队列。排课版本存于课程；计划条目按中国时间即时计算，不为未来课程批量写数据库。实际结果沿用同课同日唯一记录，旧记录默认出席。出席和课时消耗分别汇总。新增一个跨课程记录处理页与复用的简洁结果编辑弹层。

**Stack:** 微信原生 WXML / WXSS / JavaScript、微信云函数、Node 内置测试。

## 验收边界

- 每门课程每天最多一节。出席扣 1 节；缺席默认不扣，可选择扣 1 节；停课不扣。
- 上课结束后才成为待确认，绝不自动判缺席；扫描排课开始以来所有未处理日期。
- 旧手写上课备忘不自动猜测为排课。首次设置明确开始日期；已有排课修改从未来日期生效，不覆盖历史。
- 保留初始课时、归档记录、备注、导出、离线操作及账户切换保护。
- 首页顶部两条紧凑提示：全课程最近一次上课、未确认数量。
- 新增与编辑课程仍为原页面三个分区；统计页保留七日趋势、月度、课程分布和明细。
- 不新增微信推送提醒、多人共享、复杂调课；不发布公开版本、不推送 GitHub。

## 数据约定

- `scheduleVersions`: 按 `effectiveFrom` 排序的 `{ effectiveFrom: 'YYYY-MM-DD', slots: [{weekday: 0..6, start: 'HH:mm', end: 'HH:mm'}] }`。空 slots 表示停止排课，每天至多一个时段。
- 修改请求 `scheduleChange` 包含上述字段与用户发起修改的 `requestedOn`；离线请求保留原发起日。已有排课要求 effectiveFrom 晚于 requestedOn，不能覆盖已开始的版本；请求带稳定 operationId 防重试重复。
- 实际结果 `status`: attended / absent / cancelled；`debit`: 1 / 0；`reason` 与 `notes`。旧记录缺少 status 时视为 attended / 1。
- 结果更正使用稳定操作编号与记录 revision，重试不重复扣课，冲突不静默覆盖。撤销新版结果保留内部版本标记，界面回到计划待确认，不把停课当撤销。
- 归档保留已发生计划与记录，并终止未来排课；恢复后重新设置未来安排，不回补归档期间的缺席。

### 实际验收脚本（仅使用新建的明确命名验收课程）

1. 新建“排课验收 · 临时课程”，总课时 10、初始已上 0，选择每周日 10:00—11:00，开始日明确为 2026-10-04（验收当日，时段已经结束）。原拟选择多个过去日期，因原生日期滚轮自动操作不稳定，改用当天结束的时段；历史遗漏由自动测试覆盖。
2. 首页把最近上课放在课程列表前；当天结束的计划显示待确认 1。跨较早遗漏日期的完整扫描另由自动测试验证。
3. 当天这条确认缺席、不扣课，填写简短备注：出席为 0、消耗为 0、余额为 10。
4. 将同条缺席更正为扣 1 节：出席仍为 0、消耗为 1、余额为 9；重启读取一致。
5. 把同条更正为出席：出席变为 1、消耗仍为 1、余额仍为 9；月度与七日趋势仅增加这一次出席。
6. 验证全部、待确认、出席、缺席筛选与备注；重开页面后读取一致。
7. 将验收结果撤销，核对累计恢复；归档验收课程，确保不影响用户课程、不再提示未来排课。保留可恢复的验收课程及内部操作记录，不永久删除云数据。
